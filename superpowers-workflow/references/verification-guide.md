# 完成验证指南

## 完成验证清单

在声称完成前，必须确认：

- [ ] 运行了完整的测试命令
- [ ] 查看了完整输出，确认 0 failures
- [ ] 运行了 lint/type 检查并通过
- [ ] (仅 Web 应用) 使用浏览器工具验证了新功能（参见 SKILL.md "Web 验证工具选择"）
- [ ] 提供了实际的命令和输出证据

**无法勾选所有项？说明没有真正验证，需要运行验证命令。**

---

## 验证步骤详解

### 测试验证

**命令示例**:
```bash
# 运行所有测试
npm test

# 或项目特定命令
pnpm test
yarn test
pytest
go test ./...
```

**必须确认**:
- 退出码为 0
- 输出显示 0 failures
- 无错误或警告

**证据格式**:
```
测试命令: npm test
退出码: 0
输出:
  Tests:       42 passed, 0 failed
  Coverage:    85%
```

### Lint/Type 检查

**命令示例**:
```bash
npm run lint
npm run typecheck
tsc --noEmit
eslint .
```

**必须确认**:
- 无 lint 错误
- 无类型错误
- 可接受的警告（如果有）

### 浏览器验证 (仅 Web 应用)

**注意**: 非Web应用项目跳过此步骤，使用命令行测试即可

**工具选择**: 参考 SKILL.md "Web 验证工具选择" 章节，选定后本阶段统一使用

**验证内容**:
1. 打开相关页面
2. 确认新增/修改的元素已存在
3. 测试交互功能是否正常
4. 验证用户流程完整性
5. 截图对比改动前后

**证据格式**:
```
验证项目: 用户登录功能
验证结果:
  - 登录按钮存在 ✓
  - 点击后跳转正确 ✓
  - 错误提示显示 ✓
  - 截图对比: 改动前/改动后
```

## 禁止的表述

以下表述说明没有真正验证:

| 禁止 | 替代 |
|-----|------|
| "应该没问题了" | "测试全部通过，输出如下..." |
| "可能可以了" | "验证命令结果: 0 failures" |
| "看起来没问题" | "截图显示功能正常工作" |
| "应该通过了" | "实际运行结果: [粘贴输出]" |

---

## 验证发现 Bug 时

1. 停止验证
2. 调用 Skill(skill="superpowers:systematic-debugging")
3. 修复后重新执行本阶段验证
4. 不要声称完成，直到所有验证通过

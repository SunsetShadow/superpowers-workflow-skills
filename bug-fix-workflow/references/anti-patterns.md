# Bug 修复反模式

## 流程类错误

| 错误做法 | 正确做法 |
|---------|---------|
| 还没复现就猜原因改代码 | 必须先复现，确认可稳定复现 |
| "看起来是这个问题，改一下试试" | 先复现 → 调试 → 确认根因 → 修复 |
| 无法复现但先改了再说 | 多次尝试后仍无法复现 → 代码审查分析 |
| 直接看代码找问题 | 必须先尝试复现，多次失败后才能看代码 |

---

## 调试类错误

| 错误做法 | 正确做法 |
|---------|---------|
| 修复表面症状 | 必须找到根本原因，否则会复发 |
| "我大概知道原因，直接修" | 必须验证假设，确认根因后修复 |
| 加个 try-catch 隐藏错误 | 找到根因并修复，不是隐藏 |
| 修了多个"可能的问题" | 逐一验证，确认哪个是根因 |

---

## 测试类错误

| 错误做法 | 正确做法 |
|---------|---------|
| 跳过测试直接写修复 | 没有失败测试 = 无法证明修复正确 |
| 先写修复再补测试 | 必须先写失败测试，确认因 Bug 失败 |
| 测试因语法错误失败 | 修复语法，确保因 Bug 功能缺失失败 |
| "bug 太简单不用写测试" | 简单 bug 也需要测试，防止回归 |

---

## 验证类错误

| 错误做法 | 正确做法 |
|---------|---------|
| "应该没问题了" | "复现步骤执行后 Bug 不再出现" |
| "可能可以了" | "测试命令结果: 0 failures" |
| "看起来正常了" | "修复前截图 vs 修复后截图" |
| "本地测过了" | 提供可重复的验证证据 |
| 只验证修复，不验证回归 | 必须确认相关功能仍正常 |

---

## 代码类错误

| 错误做法 | 正确做法 |
|---------|---------|
| 夹带其他功能改动 | 一个 bug 一个 PR，禁止夹带 |
| "顺便"重构相关代码 | 单独 PR |
| 修复时写额外功能 | 只写让测试通过的最小代码 |
| 保留"参考"代码 | 删除所有非必要代码 |

---

## 快速自检

如果发现自己有以下想法，立即停止:

- [ ] "直接改一下试试"
- [ ] "应该是这个问题"
- [ ] "先改了再说"
- [ ] "这个小 bug 不用测试"
- [ ] "顺便优化一下"
- [ ] "本地跑过了，应该没问题"

**出现以上想法时，返回对应阶段重新执行。**

---

## 核心原则

```
1. 复现优先: 无法复现 = 无法确认修复，禁止猜测性修改
2. 证据驱动: 每一步都要有证据，禁止"应该没问题"
3. 测试先行: 先写失败测试，再写修复代码
4. 根因修复: 修复根本原因，而非表面症状
5. 单一修复: 一个 bug 一个 PR，禁止夹带其他改动
```

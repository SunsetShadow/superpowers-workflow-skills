# 无法复现时的处理流程

## 铁律

```
禁止跳过复现步骤直接看代码
```

---

## 渐进式处理

```
Step 1: 核对环境差异 (版本/配置/数据)
    ↓ 仍失败
Step 2: 请求更多信息 + 添加日志重试
    ↓ 仍失败
Step 3: 代码审查分析 (多次尝试后才可进行)
    ├─ 找到可疑代码 → 添加测试验证
    └─ 无法定位 → 标记"待观察"
```

---

## Step 1: 核对环境差异

检查项：
- [ ] 版本一致 (node/npm/依赖版本)
- [ ] 配置一致 (环境变量/配置文件)
- [ ] 数据一致 (数据库/缓存/种子数据)

示例：
```
用户环境: Node 18.17.0, Chrome 120
我的环境: Node 20.10.0, Chrome 122
→ 切换到 Node 18.17.0 重试
```

---

## Step 2: 请求更多信息 + 添加日志

请求用户：
- 完整的错误截图/录屏
- 浏览器控制台日志
- 服务端日志
- 操作步骤的详细描述

添加调试日志：
```javascript
// 在可疑位置添加
console.log('[DEBUG] input:', input);
console.log('[DEBUG] state:', state);
```

---

## Step 3: 代码审查分析

**前提**: 已尝试 Step 1-2 多次仍无法复现

分析方向：
1. 查看涉及功能的代码路径
2. 检查边界条件和异常处理
3. 查看最近的提交记录

找到可疑代码后：
- 添加针对性测试验证假设
- 如果测试能复现 → 进入正常修复流程

无法定位时：
- 标记为"待观察"
- 建议添加更详细的日志
- 记录到已知问题列表

---

## 禁止事项

| 禁止 | 原因 |
|-----|------|
| 直接看代码找问题 | 必须先尝试复现 |
| 无法复现就随便改代码 | 无法验证修复是否有效 |
| 忽略 Bug 报告 | 需要记录跟踪 |
